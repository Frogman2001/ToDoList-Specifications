# Development Working

Where the developer runs this phase’s BMAD workflow. See [Development](../README.md) for this phase and the [pipeline README](../../README.md) for the shared rules.

## What to put here

Drafts, memlogs, intermediate notes, and other scratch the workflow produces while it turns the architecture into specs, stories, and plans. Work from [2-1_InputDocs](../2-1_InputDocs/README.md) and [2-2_ProcessedDocs](../2-2_ProcessedDocs/README.md).

When the workflow finishes, write those deliverables to [2-4_OutputDocs](../2-4_OutputDocs/README.md). Leave the working files here.

Do not write application code in this folder. Implementation belongs in the ToDoList repository.

## What not to do

- Do not treat files here as the phase deliverable. QA must not copy from this folder.
- Do not write workflow output into InputDocs or ProcessedDocs.
- Do not edit Architecture OutputDocs, the PO originals, or the InputDocs snapshots from this workflow.

## Where the workflow reads and writes

Read InputDocs and ProcessedDocs. Write scratch here. Write only finished specs, stories, and plans to OutputDocs.
