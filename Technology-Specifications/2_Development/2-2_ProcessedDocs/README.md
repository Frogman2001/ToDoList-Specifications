# Development ProcessedDocs

The developer’s analysis of the frozen inputs. See [Development](../README.md) for this phase and the [pipeline README](../../README.md) for the shared rules.

## What to put here

After reading [2-1_InputDocs](../2-1_InputDocs/README.md), record which files apply to development and which parts of each file apply. Note anything the workflow must keep, ignore, or resolve. Write that analysis here in files you can revise as understanding changes.

This folder is the phase’s interpretation. It is not a second copy of the inputs and not the development deliverable.

## What not to do

- Do not edit InputDocs. Refer to them by filename.
- Do not run the BMAD workflow here, and do not leave workflow scratch here.
- Do not put finished specs, stories, or plans here.

## Where the workflow reads and writes

Read InputDocs and the notes in this folder. Run the development BMAD workflow in [2-3_Working](../2-3_Working/README.md). Write finished specs, stories, and plans to [2-4_OutputDocs](../2-4_OutputDocs/README.md).
