- (constraint) Parent spine architecture-ToDoList-2026-11-04 is binding: paradigm client-computed-views, AD-1 through AD-15. Projects remain ToDoList.Api, ToDoList.Core, ToDoList.Scheduling, ToDoList.App, ToDoList.Tests, web, and contracts. No added project. Cosmos stays a concrete class in the API. Web references neither C# project. Stack pins from that spine stay.
- (decision) AD-16 Concrete layers. Presentation is web and ToDoList.App. View rules are ToDoList.Scheduling plus a TypeScript port in web. Item model, schema conversion, and the field check are ToDoList.Core. HTTP endpoints are a presentation folder in ToDoList.Api. Cosmos access is a data folder in ToDoList.Api. Each client has an HTTP folder that calls the Function App. Binds every application project. Prevents a new infrastructure project or a layer that exists only as an interface.
- (decision) AD-17 Dependency direction. Core references no sibling project. Scheduling references Core. Api references Core and does not reference Scheduling. App references Core and Scheduling. Web references neither. Api presentation may call auth, the field check, and the Cosmos class. The Cosmos class may call Core converters. Auth does not call Cosmos. On each client, presentation calls one session type, and that session calls view rules, the field check, and the HTTP client. Binds all projects. Prevents the API computing Today, or the web compiling against C#.
- (assumption) Scheduling uses Core.Item. MAUI calls Core.ItemRules before send. The API calls ItemRules once on each write. After that check, convert and save trust the values. Web reads contracts/item-fields.json in TypeScript and does not call Core.
- (decision) AD-18 One contracts directory. contracts/item-fields.json and contracts/view-examples.json remain the only source copies. Core, the API content root, xUnit, and Vite read those files. Binds Core, Api, Tests, and web. Prevents a second edited copy of a limit or a view example inside a project.
- (assumption) How the single contracts directory is mounted (project link, content copy to output, or Vite alias) is an implementation detail. The source files stay in one directory.
- (assumption) AD-19 One session type per client. ToDoList.App ItemSession and web itemSession hold the loaded items, hide-completed, and snapback. Pages and components call that type. No CommunityToolkit.Mvvm, no Redux, no React Router. Hide-completed uses Android Preferences and web localStorage.
- (assumption) AD-20 Platform UI only. Web uses tokens.css, one stylesheet, the Google Identity Services script, pointer events for drag, and an in-app date field. Android sign-in uses Credential Manager via Xamarin.Google.Android.Libraries.Identity.GoogleId 1.1.0.16. No Tailwind, no component kit, no drag library, no date-picker library.
- (version) Checked NuGet on 2026-11-06: Microsoft.Azure.Cosmos 3.63.3 (stable, netstandard2.0, usable on net10.0). Google.Apis.Auth 1.78.0. Xamarin.Google.Android.Libraries.Identity.GoogleId 1.1.0.16, which depends on Xamarin.AndroidX.Credentials 1.6.0.1 and lists net10.0-android.
- (decision) AD-21 Tests cover Core and Scheduling only. ToDoList.Tests does not reference ToDoList.Api. No Cosmos interface is added so a test can fake storage. The emulator stays a local run. Binds Tests and Api. Prevents an API test pyramid that would force a storage port.
- (assumption) Today, day, and week are modes of one Board surface on each client. Android opens on AddNewPage. Web opens on week mode. Android sign-in is a prompt from the session when a save needs it, matching the experience spine.
- (assumption) Sizing sketch, not a schedule: about 60 authored source files. Libraries and the API are the smaller part. Each client is larger. Time concentrates in phone gestures, web drag and keyboard, the date field, and the Cosmos etag plus transactional batch. One engineer who knows this stack, a few weeks, not a multi-team program.
